1. КАК Я ЭТО ПОНИМАЮ (кратко для кодера)
--------------------------------------------------------------------------------

• Триггер: игрок подходит к NPC на дистанцию ≤ 1.5 → пауза → модальное окно.
• Старт: случайная «входная» реплика брокера (пул A).
• **Первый экран выбора** (после A): до **5** слотов; обязательные **типы** — мирный тон (**B**), угроза (**C**), ярость (**R**), соблазн (**U** при активном MB). Текст для слота **B** — **одна** случайная строка из пула B на это открытие события; для **C** — **одна** случайная из пула C (**не** пять разных угроз на одном экране — иначе забит слотами). **L** («не плачу») и **M** («договориться иначе») — **только** на экранах **ветки оплаты** (после требования золота), не на первом экране.
• Игроку на соответствующих шагах показываются варианты:
  - «Мирные / осторожные» (**B**) — ведут к ветке про ОПЛАТУ золотом.
  - «Угрожающие» (**C**) — ведут к АГРЕССИИ (ответ бандита из пула **D** → «Далее» → бой / засада по EventCore).
• Ветка оплаты:
  - Брокер называет сумму (плейсхолдер (---) → подстановка из данных события).
  - Если золота достаточно → показываются только варианты СОГЛАСИЯ заплатить (пул E, 5 шт.).
  - Если недостаточно → реплики ГГ с фактическим балансом (пул F); дальше развилка по % от запрошенной суммы:
      · сумма игрока в диапазоне ~80–99% от запрошенной → «уступка» брокера, принять меньше (пул G), проход безопасен;
      · сумма < ~80% → брокер берёт деньги + требует «доплату телом» (пул H);
          – отказ ГГ (пул I) → агрессия (как ветка C);
          – согласие ГГ (пул J) → одобрение брокера (пул K) → «Далее» → H-сцена (event), после — забирается золото.
  • Отказ платить вообще (пул L) → агрессия.
• Доп. ответ на экране оплаты: «договориться по-другому» (пул M):
  - 70% — брокер сразу предлагает «развлечься телом» (пул N) → да/нет (покорные O / мягкий отказ P);
      · да → одобрение (пул K) → H;
      · мягкий отказ → брокер «всё равно возьму» (пул Q) → агрессия;
  - 30% — сразу ветка «мало денег → тело» (как пул H).
• Ярость (Rage): пул R **всегда в списке ответов** на шаге выбора.
  - **Серые** (неактивно), пока `RagePercent < RageLinesMinPercent` (**дефолт 5%** из конфига события).
  - **Красные и активно** при `RagePercent >= RageLinesMinPercent` — тогда игрок **может** выбрать угрозу; при ровно 5% ярости линейный шанс успеха тоже **5%** (см. ниже).
  - Ответ брокера на выбор из R: пул S («испугался», пропускает) или пул T («не испугался»).
  - **ЗАФИКСИРОВАНО:** `P(S) = clamp(RagePercent / 100, 0, 1)`; `P(T) = 1 − P(S)`. Опционально в конфиге пол **`RageScareChanceFloor`** (нижний порог вероятности при активной R — если понадобится тюнинг).
  - Если выпал **T**: цепочка **та же**, что после угрозы **C** — случайная реплика из **T** → шаг **`continue`** → тот же сценарий агрессии / амбуша, что и после **D** (общий шаблон **`template_aggression_after_broker_retort`** в JSON).
• MindBroken: розовые реплики пула U при `MB >= MbTemptLinesMinPercent` (**дефолт 20%**, значение — в конфиге события); при выборе — **+10% MB** сразу, затем случайная реплика брокера из **V** (принимает «соблазн»); далее **`continue`** → **H-сцена** (тот же класс исхода, что **J → K**: добровольное тело по смыслу). Золото ГГ **не** списывается за сам факт выбора U (нет оплаты монетами); после сцены — при необходимости **`POST_H_TAKE_GOLD`** по данным события (как у других H-веток).

Интерфейс: широкая панель снизу (~1600 px), сверху реплика брокера, ниже слоты ответов.
• **Шаг «только продолжить»** (реплика брокера после выбора, монолог перед боем и т.п.): **единственная активная команда — «Далее»**, горячая клавиша **1**, первый слот UI; остальные слоты скрыты или пустые.
• **Шаг «выбор игрока»**: до **5** вариантов, клавиши **1–5** и клик по слотам.
• Реплики ярости/MB на шаге выбора **всегда в списке**; ярость — серые при ярости **ниже** `RageLinesMinPercent`, красные при **≥** порога; MB — серые ниже `MbTemptLinesMinPercent`, розовые при достаточном MB.

### 3.1 Числа 80 / 70 / 30 в конфиге события (для ясности)

Это **три разных правила**, все задаются полями JSON определения встречи (имена ниже — предложение для схемы):

| Что в игре | Смысл | Поле / дефолт |
|------------|--------|----------------|
| **80%** | Недостаточно полной суммы, но если у ГГ есть **≥ 80% от запрошенного** — брокер идёт на **уступку** (ветка G), без «тела». | `tollAcceptGoldRatio` = **0.80** |
| **70%** | При выборе «договориться иначе» (M) — **эта доля** уходит в сценарий «предложи развлечься телом» (N → O/P/K/Q). | `negotiateBodyOfferWeight` = **70** |
| **30%** | Оставшийся вес того же броска — сразу ветка как при нехватке до «тела» (как H). | `negotiateBodySkipWeight` = **30** |

Итого: это **не одно число**, а **порог золота** и **веса RNG** для отдельных развилок; в JSON их задаёшь явно, чтобы править баланс без правки кода.

5. ИНТЕРФЕЙС (резюме из автора + зафиксированные правила)
--------------------------------------------------------------------------------

• Нижняя широкая панель (~1600 px по ширине экрана).
• Сверху — текущая реплика брокера (или системное сообщение шага).
• **Шаг продолжения:** только **«Далее»** → слот **1**, клавиша **1**; **Submit (`E`)** дублирует то же действие (единый выход после паузы на таких экранах).
• **Шаг выбора:** до **5** вариантов, мышь + **1–5**.
• Строки ярости и MindBroken на шаге выбора — **всегда в списке**:
  - ярость **ниже** `RageLinesMinPercent` (дефолт **5%**) — пул R **серый**, неактивный;
  - ярость **≥** порога — R **красный**, активный;
  - MB **ниже** `MbTemptLinesMinPercent` (дефолт из конфига, обычно **20**) — U серый;
  - MB **≥** порога — **розовый**, активный (штраф +10% MB при выборе — по дизайну).


--------------------------------------------------------------------------------
6. ЗАМЕТКИ ДЛЯ ПЕРЕНОСА В JSON (зафиксировано + мелочи)
--------------------------------------------------------------------------------

• **`RageLinesMinPercent`** = **5** (дефолт): ниже — R серые; от 5% — красные и кликабельно; линейный шанс S совпадает с % ярости (на 5% ярости — 5% на S).
• **`MbTemptLinesMinPercent`** — в конфиге события (дефолт **20**).
• **`REQ_GOLD`**: дефолт контента **500** до формулы; подстановка во **второй** слот F и в реплику «назови цену» — всегда из данных события (динамика).
• **`tollAcceptGoldRatio`**, **`negotiateBodyOfferWeight`**, **`negotiateBodySkipWeight`** — см. §3.1.
• Успех угрозы (**пул S**): показывается **случайная реплика из S** (брокер капитулирует), затем шаг **`continue`** («Далее») → **`ContinueUnifiedResolve`** → проход / конец таксации по сценарию — **без пропуска** текстов S.
• **`ContinueUnifiedResolve`** обязателен для **каждого** шага `continue` (время, `_SOUSA`, флаги EventCore).
• **ЗАФИКСИРОВАНО:** на `continue` — **и клавиша 1, и Submit (`E`)**; золото — см. **`GOLD_DEBIT_TIMING`** в таблице §3.

**Шаблоны графа:** см. §8 (`template_aggression_after_broker_retort`, первый экран vs экран оплаты).

--------------------------------------------------------------------------------
8. ГРАФ JSON — шаблоны и полнота контента
--------------------------------------------------------------------------------

**Контент пулов A–V + `POOL_BROKER_DEMAND` (§4.5)** — достаточно для сборки события; отдельные «дыры» в фразах не остаются.

**Шаблоны (рекомендуется один раз описать в JSON и переиспользовать ссылки):**

| Id | Когда |
|----|--------|
| **`template_aggression_after_broker_retort`** | После пула **D** (угроза C) **или** после пула **T** (ярость не увенчалась): случайная реплика реторта → `stepKind: continue` → эффекты агрессии / амбуш / флаги EventCore (как в **`POOL_PC_THREAT`**). |
| **`template_pass_after_rage_scare`** | После пула **S**: реплика → `continue` → **`ContinueUnifiedResolve`** → проход без боя (конец таксации по данным события). |
| **`template_h_after_body_offer`** | После **K** или после **V**: `continue` → запуск H-сцены по id события → опционально **`POST_H_TAKE_GOLD`**. |

**Разделение экранов**

• **`step_open_after_A`** — только **B / C / R / U** (по правилам серого/красного/розового); **без L и без M**.  
• **`step_pay_resolution`** — экраны с **E / F / G / H / I / J / K / L / M / …** по условиям золота и веток из §1.

**Порядок слотов на первом экране** — на усмотрение JSON (обычно 1=B, 2=C, 3=R, 4=U при наличии MB); главное — не превысить **5** активных и не смешать старт с экраном оплаты.
